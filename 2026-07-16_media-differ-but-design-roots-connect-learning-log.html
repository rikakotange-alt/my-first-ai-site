Learning OS｜2026.07.16

デザインカンプを調べ始めたことから、Webデザイン、動画制作、マーケティング、コメント分析の間に、共通する設計の流れがあるように感じた朝の記録です。

Beginning

今朝、「デザインカンプって何だろう」から調べ始めた

以前のFigma講座で、Webサイト制作ではコーディングをする前にデザインカンプを作ると知りました。

言葉の意味としては、Webサイトの完成見本のようなものだと分かります。でも、私は実際のWebデザインの仕事を見たことがありません。

デザインカンプは誰が作り、誰が受け取り、そこからどのように本物のWebサイトになるのか。その流れがまだ頭の中でつながっていなかったので、今朝あらためて調べ始めました。

From Comp to Code

完成見本を見るだけではなく、Webの部品へ読み替えていく

初心者向けの動画では、デザインカンプを確認し、HTMLやCSSを書く前にコーディングの計画を立て、文章や画像を準備し、最後にブラウザ上の見た目をデザインカンプへ近づけていく流れが紹介されていました。

HTMLやCSSの細かい内容は、まだ私にはよく分かりません。

それでも、デザインカンプは単なるきれいな画像ではなく、その後にWebサイトを作る人が、文字の大きさ、色、余白、画像、レイアウトなどを読み取るための設計図のような役割もあるのかな、と少し見えてきました。

Roles

役割を分けると、連携の流れが少し見えた

マーケター

何を売り、誰に、どう訴求するかを考える。

コピーライター

相手に伝わる言葉を作る。

Webデザイナー

言葉や情報を、読みやすく行動しやすい画面にする。

コーダー

その画面を実際に動くWebサイトにする。

それぞれ別の仕事ですが、完全に切り離されているわけではなく、ひとつの制作の中で連携しているように見えました。

AI and Domain

ここで、以前に知った「領域」ともつながった

以前は、マーケター、コピーライター、Webデザイナー、コーダーのように、それぞれの領域を別の人が担当していた仕事が多かったのだと思います。

今はAIを活用することで、一人の人が企画、文章、デザイン、コーディングなどの作業を、それぞれ得意なAIツールへ役割分担させながら進められるようになってきました。

以前の分業

人間の専門家が、それぞれの担当領域を受け持って連携する。

AIを使う現在の進め方

一人の人間が複数の領域を横断し、工程ごとにAIツールを使い分けながら制作を進める。

だから「一人でも作れる」がすごいのかもしれない

以前なら複数人の専門家が必要だった制作の一部を、一人がAIへ役割分担させながら進められる。コーディングも、その支援対象に含まれています。

ただ、AIがそれぞれの専門家そのものになるというより、一人の人間が複数職種の作業を横断しやすくなった、と考える方が近そうです。

ここで、以前に学んだ「領域」という考え方ともつながりました。

AIツールだけを知っていても、マーケティング、文章、デザイン、コーディングの各領域で、本来何を考え、何を判断する仕事なのかが分からなければ、出力が合っているかを確かめにくいです。

領域を知ることが、AIへ仕事を振るための土台になる

その領域では何を目的とし、どんな工程があり、何を人間が判断するのかを知る。その上でAIを使うから、何を任せ、何を確認すればよいかが見えてくる。

「AIツールは会社の部署」という以前の理解も、ここで少し具体的になりました。部署を増やすだけでは制作は進みません。どの領域の、どの仕事を、どの部署へ渡すのかを考える人が必要です。

まだ各領域の仕事を十分に理解しているわけではありませんが、AIのすごさを知るためにも、先に人間の仕事と領域を知る必要があるのだと思いました。

The Root

媒体ごとに枝葉は違っても、根っこは同じなのかもしれない

Webデザインについて調べていくと、広告やランディングページの仕事が多く、マーケティングとの距離が近いことも分かってきました。

今朝見えた共通する根っこ

相手を理解し、情報の順序と見せ方を設計し、次の行動へ導くこと。

媒体によって表面に見える作業は違いますが、下にある考え方はつながっているように感じました。

Marketing

マーケティング

ターゲットや訴求を決める。根っこにあるのは、誰に何を届けるかを考えること。

Web Design

Webデザイン

LPの画面や導線を作る。根っこにあるのは、情報をどの順番で見せるかを考えること。

Video

動画制作

企画、構成、編集をする。根っこにあるのは、離脱させずに理解や感情を運ぶこと。

Copywriting

コピーライティング

見出しや文章を書く。根っこにあるのは、相手が自分のこととして受け取れる言葉を選ぶこと。

Observation

コメント分析

反応を分類し、観察する。根っこにあるのは、人が何に動いたのかを知ること。

AI

AI活用

各工程を生成したり短縮したりする。人間が決めた方向を、形にすることを支援する。

LP and Video

ピラティスLPの流れを動画へ置き換えてみた

LPの場合

悩みを提示する → 解決できる理由を見せる → 安心材料を置く → 料金を示す → 予約へ導く。

動画の場合

視聴者の悩みや関心を提示する → 解決の可能性を示す → 根拠や具体例を見せる → 内容を理解してもらう → 登録、購入、次の動画などの行動へ導く。

こうして並べると、Webデザインと動画制作は違う媒体を扱っていますが、企画、相手の理解、構成、見せ方、行動喚起が土台にある点は似ています。

Comment Analysis

コメント分析も、感想整理だけではなかった

これまで行ってきたコメント分析も、動画の感想を分類していただけではなかったのかもしれません。

人はどこで注意を止めたのか

どの言葉、人物、場面、テーマに反応したのか。

何に共感し、何を嫌がったのか

どこで自分事になり、どこで違和感や反発が生まれたのか。

何を信じたのか

誰の言葉、どんな根拠、どんな見せ方が受け入れられたのか。

相手の反応を観察することは、次の企画や構成、見せ方を考えるための材料にもなっていたのだと思います。

Common Flow

AIツールも、共通の制作フローに置くと役割が見えやすい

共通する流れ

相手を知る → 伝える内容を決める → 順序を設計する → 見える形にする → 反応を観察する → 改善する。

ChatGPT、Figma、Canva、CapCut、Codexも、別々の島として覚えるより、同じ制作の流れの中で担当する場所が違う道具として見ると、少し分かりやすくなりました。

まだ各ツールや各職種を十分に理解しているわけではありません。ただ、別々に見えていたものが、同じ川の異なる工程に置かれた水車のように見え始めています。

Fieldwork

Webデザイン探索は、進路探しではなかった

その後、Webデザイナーについての動画をいくつか見ました。

でも、見れば見るほど、Webデザインという業界そのものは私にはあまり合わないように感じました。

AIがどうという話ではなく、流行や見た目の正解を追う感じ、業界特有のテンションや言葉づかい、制作物そのものよりも「売れる見せ方」が強く求められる感じに、少し距離を感じました。

ただ、だからといって、今回調べたことが無駄だったわけではありません。

今回のWebデザイン探索は、進路探しではなくフィールドワークだった

Webデザインという領域から、誰に届けるか、情報をどう並べるか、どこへ視線を導くか、どうすれば伝わりやすくなるかという制作OSの部品を持ち帰るための探索でした。

私は、業界の中へ入って流行や競争へ自分を合わせ続けるよりも、少し外側から観察して、この仕事は何を設計しているのか、どこが動画制作とつながるのか、自分の制作OSへ何を移植できるのかを拾う方が合っているのだと思います。

Webデザイナーになるためではなく、Webデザインという領域の設計思想を、自分の動画制作やCodexへ持ち帰った。

今の自分に近い方向

売れる形へ自分を寄せ続けるより、自分の観察や問いを、伝わる形へ設計したい。

この違いが、私にとってはかなり大きいのだと思います。

Where I Am Now

理解できたというより、つながった感覚を残しておく

Webデザインもデザインカンプも、今日知り始めたばかりです。

今の時点で、仕事の全体像を理解できたとは言えません。専門用語も実際の作業も、まだ頭へ落とし込めていない部分が多くあります。

それでも、マーケティング、Webデザイン、動画制作、コピーライティング、コメント分析が、それぞれ孤立した技術ではなく、相手を理解して情報と行動を設計するという共通の根を持っているように感じました。

そして、その根をたどっていくと、最後は設計図へ戻ってくるようにも思います。

AIツールを使えるだけではなく、マーケティング、文章、デザイン、コーディングの各領域で、本来何を目的にし、どこを人間が判断するのかを知らないと、AIの出力を確認できません。

以前に知った「領域ファースト」と「AIツールは会社の部署」という考え方が、今日ようやく具体的な仕事の流れとしてつながったように感じます。

完成物の前にある、見えない設計

誰に届けるのか。何を伝えるのか。どの順番で見せるのか。どこで安心してもらうのか。どの行動へつなげるのか。
