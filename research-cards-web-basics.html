RESEARCH CARDS｜2026.07

Web制作の基礎棚

Claude Code入門で整理したWeb制作の基礎を、あとから見返せる研究カードとして標本化した棚。学習ログは日付つきで流れを記録し、研究カードは作成月単位で整理する。『作る・保存する・公開する』の違いを、料理や店舗運営の比喩も使いながら、自分の言葉で再構造化した。

2026.07｜WEB-01

HTML / CSS / JavaScript

HTMLは骨組み、CSSは見た目、JavaScriptは動き。Web制作では、この3つがそれぞれ別の役割を持ちながら、ひとつのページを形づくっている。細かい文法を全部覚えるより、まずは『骨組み・見た目・動き』の役割の違いを見分けられることが土台になる。

HTML CSS JavaScript Web制作 基礎構造
2026.07｜WEB-02

「作る」と「公開する」は別作業

サイトを作ることと、サイトを公開することは同じではない。料理で言えば、作って皿に盛るところまでが制作で、テーブルに出して誰でも食べられる状態にするところが公開。この違いが見えると、制作途中の作業と公開準備の作業をごっちゃにしにくくなる。

公開 Web制作 Pages 比喩
2026.07｜WEB-03

ホームページ制作とアプリ開発の違い

ホームページ制作は、情報を見せることが中心の構造。一方でアプリ開発は、入力・保存・更新・動作確認など、より多くの処理や管理が関わる。料理の比喩で言えば、ホームページ制作は厨房の作業員、アプリ開発は店長やマネージャーのように、扱う範囲と責任が広くなる。

ホームページ制作 アプリ開発 制作比較 比喩
2026.07｜WEB-04

Codex・GitHub・GitHub Pagesは別の役割

Codexは作る支援をするAI、GitHubはコードや変更履歴を保存する保管庫、GitHub Pagesは保存したものをWeb上で公開する場所。この3つは似て見えても、役割はまったく違う。『AIは作る・GitHubは保存する・Pagesは公開する』と分けて考えると、全体の流れがかなり整理しやすくなる。

Codex GitHub GitHub Pages 役割分担
2026.07｜WEB-05

GitHubは“保管庫”である

GitHubは単なるファイル置き場ではなく、変更履歴を残しながら安全に保管できるクラウド上の保管庫。どこを直したか、いつ更新したかを記録しながら管理できるので、制作物を育てていく土台になる。あとから修正や改善を重ねていく前提で考えると、GitHubは制作の記録装置でもある。

GitHub 保管庫 変更履歴 更新管理
2026.07｜WEB-06

なんとなくを設計指示に変える

AIに『なんとなくこうしたい』と伝えるときも、役割や目的を少し分解して伝えるだけで、指示はかなり通りやすくなる。詳しく伝える、エラーメッセージを見せる、画面を共有する、困ったら見直す。こうしたやり方は、“なんとなく”を設計指示へ変えていく実践感覚でもある。

AI指示 設計指示 実践 トラブルシュート
2026.07｜WEB-07

公開はゴールではなくスタート

サイトは公開して終わりではなく、使いながら直し、育てていくもの。見にくいところ、足したい情報、改善したい導線を少しずつ更新していくことで、制作物も自分自身も育っていく。完璧に作る力より、公開して改善し続ける力のほうが今は大事だと実感した。

公開後運用 改善 更新 継続制作
2026.07｜WEB-08

Codexは「知の図書館」へ育つ

今回の学びを通して、Codexは単なる学習ログ置き場ではなく、研究カードや構造図を整理し、あとから再検索できる知の図書館として育てられると見えてきた。表側は検索端末図書館、裏側は研究秘書アプリ。そんな二層構造が、自分の学び方と制作テーマにかなり噛み合っている。

標本化のルール

学習ログは、その日に何を学び、どう感じたかを残すため、日付まで入れる。研究カードやStructure Diagramは、あとから見返す標本として扱うため、作成月までで管理する。

🐾 パウ所長の研究メモ：日記は日付、標本は月。研究棚に並べるときは、あとから探しやすい札をつけるワン。
